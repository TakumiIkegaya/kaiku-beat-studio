# Webアプリの構成

個人利用を想定し、無料枠を活用して運用費用を抑える構成です。
画面にHTML・CSS・JavaScript、バックエンドにPython、データベースにPostgreSQLを使用します。

## 使用するサービス

| サービス | 役割 | 配置・保存するもの |
|---|---|---|
| Cloudflare Pages | ブラウザに画面を配信 | HTML・CSS・JavaScript |
| AWS Lambda | リクエストに応じて処理を実行 | Pythonのプログラム |
| Neon | データベースを提供 | PostgreSQLのテーブル・記録データ |
| Cloudflare R2 | 音声などのファイルを保存・配信 | 音声・画像ファイル |

※音声ファイルの保存先は、当初のAWS S3からCloudflare R2へ変更した構成です。

## アプリが動く流れ

1. スマホやPCでアクセスすると、Cloudflare Pagesから画面が読み込まれます。
2. 記録の保存・取得などを操作すると、JavaScriptがAWS Lambdaへリクエストを送ります。
3. LambdaがPythonを実行し、Neonのデータを読み書きします。
4. Lambdaが処理結果を返し、JavaScriptが画面に反映します。
5. 音声や画像は、必要に応じてブラウザがCloudflare R2から取得します。

※ブラウザからNeonへ直接接続せず、Lambdaを経由します。
※Lambdaの呼び出し口には「関数URL」または「API Gateway」を使用します（未選定）。

## 稼働と休止

- Lambdaは、リクエストを処理する時だけ稼働します。
- Neonは、DBへのアクセスで起動し、一定時間使われなければ休止します。
- LambdaとNeonは、それぞれ独立して稼働・休止します。
- 休止後の最初のアクセスでは、起動のために応答が遅くなる場合があります。

「24時間いつでもアクセスできる」構成ですが、
サーバーやDBを常に動かし続ける必要はありません。

## 費用の考え方

- 個人の少量利用では、各サービスの無料枠内での運用を目指します。
- 実行回数・処理時間・保存容量・通信量によって費用が変わります。
- Neonの無料プランは、上限に達すると利用が制限されるため、使用量の確認が必要です。
- AWSの予算通知は、自動停止や請求額の上限を保証するものではありません。

## 構築時に設定すること

- Lambdaの呼び出し口と、必要なCORS設定
- ユーザー認証と、本人のデータだけを操作できる権限制御
- Neonの接続情報の安全な管理（HTML・JavaScriptには記載しない）
- 音声・画像ファイルの公開範囲
- 各サービスの使用量確認と料金通知
